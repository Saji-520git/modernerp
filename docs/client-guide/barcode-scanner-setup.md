# Barcode Scanner Setup

## Problem: Scanner adds product multiple times or presses Enter twice

When a barcode scanner sends CR+LF (two characters) after each scan instead of
CR only (one character), the POS receives two "Enter" keypresses per scan and
may add the same product twice.

ModernERP includes a 300 ms software debounce as a safety net, but the best
fix is to configure the scanner itself.

---

## Solution A — Configure the scanner suffix (recommended)

Most Honeywell, Zebra, and generic USB/Bluetooth scanners default to CR+LF.
Change it to CR only:

1. Print the configuration/programming guide for your scanner model.
2. Find the **"Suffix"** or **"Termination Character"** section.
3. Scan the **"CR only"** (carriage return, no line feed) programming barcode.
4. Test: scan any product barcode → the item should appear in the cart exactly once.

### Common scanner models

| Brand | Guide keyword |
|---|---|
| Honeywell / Metrologic | "Carriage Return Only" or "CR Suffix" |
| Zebra / Symbol | "Enter Key" → "CR Only" |
| Datalogic | "Postamble" → set to `<CR>` |
| Generic USB HID | Program with the bundled CD or manual |

---

## Solution B — Software debounce (already built in)

ModernERP automatically ignores a second scan of the same barcode within
**300 ms** of the first. This prevents double-adds even if the scanner sends
CR+LF, as long as the two Enter events arrive within that window (they always do,
since they are generated by the same hardware character).

The debounce is transparent — a skilled cashier scanning items quickly is never
affected because consecutive *different* items are always more than 300 ms apart.

---

## Testing the fix

1. Open the POS screen.
2. Scan a product barcode.
3. Confirm the cart shows **qty = 1** (not 2).
4. Scan the same barcode again — qty should become **2**.

If qty jumps to 3 on the second scan, the scanner is still sending CR+LF
**and** the two Enter events arrive more than 300 ms apart (unusual but possible
on very slow scanners). In this case, configure the scanner suffix as described
in Solution A.
